## 4. UI design — the image tile (collage + fallbacks)

Tile content, in priority order (all on the tinted `surfaceAlt` rounded square):
1. **≥1 real images** → render up to **3** product images as a light collage
   (1 image → centered; 2–3 → a small even row), `resizeMode="contain"`.
2. **0 real images** → **emoji** (the tile's existing `emoji`) — graceful, honest.

```
TILE_W square, Radius 16, bg surfaceAlt
 ├─ images[0..2] (contain) OR emoji
 └─ (label sits BELOW the tile, 2 lines, like today)
```
**Component change:** `CategorySections.tsx` `SectionTile` gains an optional
`images?: string[]` (looked up by `tile.category`). When present, render the collage;
else the current emoji. Geometry/label unchanged → alignment preserved.

## 5. Backend design — `GET /catalog/category-images`

Mirrors `getBestsellers` (1.md) but returns **all** categories as a name→images map, up
to **3** images each. Additive; `getCategories`/`getBestsellers` and their tests untouched.

> **Per `apps/api/CLAUDE.md`: pull Prisma v5 docs via Context7 before writing the query.**

```ts
// catalog.service.ts — pure, testable collapse (reuses the buildBestsellers idea).
export function buildCategoryImages(cats: BestsellerCategoryRow[], perCat = 3): Record<string, string[]> {
  const map: Record<string, string[]> = {};
  for (const c of cats) {
    const urls = c.products.map((p) => p.images[0]?.url).filter((u): u is string => !!u);
    const arr = (map[c.name] ??= []);
    for (const u of urls) if (arr.length < perCat && !arr.includes(u)) arr.push(u);
  }
  return map;   // { "Bath & Body": ["…a","…b"], "Hair Care": ["…"], … }
}

async function getCategoryImages(perCat = 3): Promise<Record<string, string[]>> {
  const cached = await redis.get(keys.categoryImages()).catch(() => null);
  if (cached) return JSON.parse(cached) as Record<string, string[]>;
  const cats = await prisma.category.findMany({
    where:   { isActive: true, shop: { isActive: true } },
    orderBy: { sortOrder: 'asc' },
    select: {
      name: true,
      products: {
        where:   { isActive: true, stockStatus: 'available', images: { some: {} } },
        orderBy: { sortOrder: 'asc' },
        take:    perCat * 2,
        select:  { images: { orderBy: { sortOrder: 'asc' }, take: 1, select: { url: true } } },
      },
    },
  });
  const result = buildCategoryImages(cats as BestsellerCategoryRow[], perCat);
  await redis.setex(keys.categoryImages(), CACHE_TTL.bestsellers, JSON.stringify(result)).catch(() => {});
  return result;
}
```
- **Route:** `app.get('/category-images', async (_q, reply) => reply.send(await catalogService.getCategoryImages()))` (public).
- **Cache:** `catalog:catimages`; bust inside `invalidateShopCache` (same as bestsellers).
- **Reuse:** `BestsellerCategoryRow` type already exists; no eggs filter needed here
  (Beauty/Household have none) — keep it simple.

> **Simpler v1 alternative (zero backend):** `getCategories()` already returns a single
> `imageUrl` per category. We could render **single-image** tiles from that with no new
> endpoint, and add the 3-image collage later. Recommended only if you want to ship without
> any backend change; the endpoint above is the faithful image-2 match.

## 7. 🔒 Security & data-integrity
| Risk | Status |
|---|---|
| PII / shop identity / price leak | ✅ endpoint returns **category names + image URLs only** — no shop, no user, no price |
| Auth | ✅ public read (same as `/categories`, `/feed`) — Home is already behind the authed stack for cart writes |
| Image safety | ✅ R2 HTTPS, EXIF-stripped WebP via the pipeline; immutable cache headers; no hotlinking |
| Fabrication | ✅ real images only; emoji fallback — nothing invented |
| Injection | ✅ navigation-only; category name is server-supplied, not user free-text |
| Staleness | ✅ Redis-cached + busted on inventory writes |
| DoS | ✅ cached read; bounded `take` per category |
